Covers: M0 · `schema/manooch.proto`, `gen/manoochv1/`

## Purpose

The wire format between Manooch and every consumer. Generated Go is committed under `gen/manoochv1/` so a consumer building against Manooch never needs `protoc`.

## Files

| Path | Holds |
|---|---|
| `schema/manooch.proto` | The contract: 5 enums, 11 messages, `proto3`, package `manooch.v1` |
| `schema/README.md` | Evolution rules and the regeneration command |
| `gen/manoochv1/manooch.pb.go` | Generated by `protoc-gen-go`; 16 Go types. Do not edit |

## Key types and functions

Enums. The Go constant for each value is the full proto name, e.g. `pb.MarketType_MARKET_TYPE_PERP_LINEAR`.

| Enum | Values beyond `_UNSPECIFIED = 0` |
|---|---|
| `MarketType` | `SPOT`, `MARGIN`, `PERP_LINEAR`, `PERP_INVERSE`, `FUTURE_LINEAR`, `FUTURE_INVERSE` |
| `Channel` | `ORDERBOOK`, `TRADES`, `MARK_PRICE`, `INDEX_PRICE`, `FUNDING`, `METADATA`, `HEALTH` |
| `Source` | `WEBSOCKET`, `REST` |
| `Status` | `HEALTHY`, `DEGRADED`, `STALE` |
| `Side` | `BUY`, `SELL` |

Messages.

| Message | Role |
|---|---|
| `Instrument` | Identity: `base`, `quote`, `settle`, `market_type`, `expiry`, `canonical`, `venue_symbol` |
| `Envelope` | Attached to every payload as field 1. Provenance, timing, sequencing, status |
| `PriceLevel` | `price`, `size` — one book level |
| `OrderBook` | `env`, `bids` (descending), `asks` (ascending), `depth` |
| `Trade`, `Trades` | `Trades` batches `Trade`; venue order is preserved |
| `MarkPrice`, `IndexPrice` | `env` plus one `int64` at price scale |
| `Funding` | `funding_rate` at rate scale `1e-12`, `next_funding_time_ns`, `interval_seconds` |
| `InstrumentMeta` | Tick/lot/min/max/notional/multiplier, `active`, `last_refresh_ns`. Nothing writes it at M0 |
| `Health` | Status, age, reconnect and restart counts, fallback flag, clock skew. Nothing writes it at M0 |

Every payload message carries `Envelope env = 1`, which is what `publish.enveloped` asserts on and how `publish.Decode` reaches the envelope without knowing the concrete type.

Envelope fields, by who fills them:

| Filled by | Fields |
|---|---|
| The producer (`internal/synth` today, a venue adapter in M1) | `venue`, `instrument`, `channel`, `exchange_time_ns`, `recv_time_ns`, `venue_seq`, `venue_seq_present`, `source`, `status`, `status_reason` |
| `publish.RedisPublisher.Publish` | `publish_seq`, `instance_id`, `schema_version`, `publish_time_ns`, and `venue` if the producer left it empty |
| Nothing at M0 | `price_exp`, `size_exp` — left at `0`, which the schema defines as "the global scale" (`-11` and `-8`) |

## How it is used

`internal/core` maps enum values to and from their config and key spellings. `internal/publish` maps a `Channel` to a concrete message type in `NewMessage`, and reads the envelope in `Publish`, `observe` and `Decode`. `internal/synth` constructs the payloads. `cmd/manooch-tap` and `cmd/manooch-status` decode them.

## Rules

- **Never renumber or reuse a field number, and never change a field's type.** protobuf decodes a changed field without complaining; a consumer deployed months ago would read the new bytes into the old meaning and report no error.
- **New fields are additive with a new number.** Old consumers ignore what they do not know, which is the only change they survive.
- **Bump `schema_version` when an existing field's meaning changes.** Same number and type with different semantics is the one change the wire format cannot signal on its own; `Envelope.schema_version` is how a consumer notices.
- **Regenerate and commit `gen/` in the same commit as the `.proto` change** (`make proto`). A `gen/` that lags the schema is a contract nobody can read.
- **Keep `Envelope` as field 1 of every payload.** `publish.Decode` and `publish.enveloped` rely on `GetEnv()` existing on every message a channel can carry.
